# DECISIONS.md

## 2026-11-17 (round 2)

- Supported install is Node `>=20` and yarn `1.22.x`. Do not use `--ignore-engines`. GitHub Pages workflow matches that (Node 20, `yarn install --frozen-lockfile`). Yarn 1 still only warns on transitive engines; the web package `engines` field plus npm `engine-strict=true` is what fails Node 18 cleanly.
- Keep both lockfiles: yarn is CI/deploy; npm lock is for `npm ci` / npm audit. They pin the same security versions. Hoist layout is allowed to differ. Yarn 1 cannot version-split `brace-expansion@1` vs `@2` in one global key; npm overrides can. Document rather than flatten npm down to yarn's single 2.1.8.
- `patch-package` is a start-path tool (WDS 5 + css-select 2 CJS default). Production `npm ci --omit=dev` must skip it, not fail. `yarn build` does not load `webpackDevServer.config.js`.
- Do not force `react-router-dom@7.18.5` (advisory range still includes all 6.x and 7.x until 7.18). 6.30.6 + `@remix-run/router@1.23.4` is the compatible 6.x patch. `moment@2.31.0` is the 2.x patch.
- Remaining 4 high are only `svgo@1.3.2` / `@svgr/*@5` / `react-scripts`. That set really does need a bundler migration. Do not claim every leftover advisory needs to leave CRA, and do not take audit's `react-scripts@2.1.3` downgrade.
- `serialize-javascript@7.1.4` is a leaf CJS pin (4.x/6.x have no patched same-major). Verified `yarn build` + tests. Not a blanket major override of the toolchain.
- `nth-check@2.1.1` remains; `nth-check@3` is ESM. css-select 2 called `require("nth-check")` as a function; unwrap `default` via patch-package instead of dropping the security pin.

## 2026-11-17

- Treat yarn as the web app package manager because `.github/workflows/static.yml` runs `yarn install` / `yarn build` in `llm-vram-calc-web`. Keep both `yarn.lock` and `package-lock.json` generated by their package managers so npm audit and yarn stay aligned.
- Pin `nth-check` to 2.1.1, not 3.0.1: 2.1.1 is the last CommonJS release that still satisfies CRA's `css-select@2.1.0`. `nth-check@3` is ESM-only (`type: module`, `boolbase@^2`, Node `>=20.19.0`) and would break that path.
- Pin `postcss` to 8.5.33, not the screenshot floor of 8.4.31. Official advisories after 8.4.31 still affect `<=8.5.22` (GHSA-qx2v-qp2m-jg93, GHSA-6g55-p6wh-862q, GHSA-fxqj-rqcc-2cmp, GHSA-r28c-9q8g-f849). Also pin `nanoid@3.3.20` and `source-map-js@1.2.2` because they are the postcss 8 runtime deps currently flagged on the same path.
- Pin `webpack-dev-server` to 5.2.7 (latest 5.x), not 5.2.1. GHSA-4v9v-hfq4-rm2v / GHSA-9jgg-88mc-972h are fixed in 5.2.1; later 2026 advisories require 5.2.6+. Do not jump to 6.1.0: it needs webpack `^5.101.0` and Node `>=22.15.0`, which is a CRA migration.
- CRA 5 still emits `https` / `onBeforeSetupMiddleware` / `onAfterSetupMiddleware`. Keep `react-scripts@5.0.1` and apply a minimal `patch-package` mapping those options to webpack-dev-server 5 `server` / `setupMiddlewares`. Verified with `yarn start` compiling and serving HTTP 200.
- Do not hide remaining CRA 5 toolchain advisories and do not run `npm audit --force` onto `react-scripts@0.0.0`. Round 2 showed several former critical/high items were same-toolchain pins; the leftover high set is `svgo@1.3.2` / `@svgr@5`.
